## 一、为什么需要它（问题定位，均有定量依据）

| 现象 | 定量证据 | 结论 |
|------|----------|------|
| 高增益下噪点明显 | 灰度模式与彩色模式**平坦区亮度 std 相同** | 噪点在**亮度域**；而 `chroma_denoise` 只对色度 Cb/Cr 做低通，**亮度 Y 一根毛都没动** ⇒ 亮度噪点从未被处理 |
| 画面发糊，不如手机 | 全链路 `RAW→HDMI` **没有任何锐化环节**；demosaic 双线性本身偏软 | 缺锐化，属结构性缺失，不是参数没调好 |
| 整体偏暗 | AE 靶亮度 120 ≈ 线性域 18% 灰 | 见 A 项：`ae_set.v` 改 145 ≈ 30% 灰 |

> ⚠️ **灰度/二值/Sobel 分支取的是 `S_video_bright`（gamma 输出）**，
> 不经本模块 ⇒ 它们完全不受影响，本模块**只作用于彩色原图通路**。

## 二、插入位置

```
gamma_lut ──► [ image_enhance ] ──► chroma_denoise ──► sat_enhance ──► MUX ──► HDMI
                     ▲ 新增
```

**为什么不放在 `sat_enhance` 之后**：`sat_enhance` 把色度放大 1.5×，
若在其后做锐化，附加的 delta 会叠在**已被放大的色度**上，更容易撞 255/0 限幅而溢色。
放在色度降噪之前，能让后续色度模块工作在"已经干净的亮度"上，顺序更符合 ISP 惯例。

## 三、算法：软阈值 Coring + Unsharp（二者共用同一个 3×3 窗口）

记 `Yc` = 中心像素亮度，`blur` = 3×3 高斯 `[1 2 1;2 4 2;1 2 1]/16` 低通亮度：

```
detail = Yc - blur                                # 带符号高通分量
cored  = sign(detail) · max(|detail| - CORE_DZ, 0) # 死区内细节归零 ⇒ 消噪
Y_dn   = blur + cored                             # 平坦区 = blur，边缘 = 保留
Y_out  = Y_dn ± (cored >>> SHARP_SH)              # 只放大"过了死区"的真实边缘
delta  = Y_out - Yc
R' = clamp(R + delta),  G'、B' 同理                # 三通道加同一 delta ⇒ 保色相/饱和度
```

**本质：按「幅度」区分噪声与边缘，而不是靠空间平滑。** 这是它能"消噪但不糊"的原因。

### 传输曲线（示例：`dz=8`、`SHARP_SH=1`，net = core + core/2）
> v6.4 起默认 `dz` 由 AE 增益自适应给出（见第四节档位表）；下表以 `dz=8` 为例说明形状。

| 输入 detail | ≤8 | 12 | 16 | 24 | 32 |
|-------------|----|----|----|----|----|
| 输出 detail | 0（全抹） | 6 (50%) | 12 (75%) | 24 (100%) | 36 (112%) |

即"死区 + 扩张"：小细节（≈噪声）被抹平，大细节（真边缘）被保留并放大。
→ **细纹理有损失是必然的物理折衷**（噪声与微纹理在单点上不可区分），
   觉得太软就把 `CORE_DZ` 调小。

## 四、参数（编译期常量，改完需重编译）

| 参数 | 默认 | 含义 | 调法 |
|------|------|------|------|
| `ADAPT_EN` | `1'b1`  | ★v6.4：降噪强度随 AE 增益自适应 | 设 0 → 用常量 `CORE_DZ`（回归固定死区） |
| `CORE_DZ`  | `8'd8`  | 细节死区（`ADAPT_EN=0` 时才生效） | 噪点仍明显 → 10/14；太软 → 4/3 |
| `SHARP_SH` | `3'd1`  | 锐化右移：0=1.0x 1=0.5x 2=0.25x 3=0.125x | 想更锐 → 0（易出白边）；溢色 → 2/3 |
| `MODE`     | `2'd2`  | 0:纯直通 1:仅降噪 2:降噪+锐化 | 上板做 A/B 逐一切换 |
| `EN`       | `1'b1`  | 总开关，0 → 退化为 MODE=0 | A/B 对比 |

### ★v6.4 自适应死区档位表（`ADAPT_EN=1` 时）

`I_ag` 是 AE 增益控制字（`O_ag`，量程 **16~239**，**32 个码字 = 1 octave**，
即 `gain = 2^((AG-16)/32)`）。噪声幅度 ∝ 增益，故死区随增益分七档：

| AG 区间 | `ag[7:5]` | 实际增益 | `dz` | 说明 |
|---|---|---|---|---|
| 16 ~ 63   | 0,1 | ≤ 2.8x  | **4**  | 明亮，尽量保细节 |
| 64 ~ 95   | 2   | ~5.7x   | **6**  | |
| 96 ~ 127  | 3   | ~11x    | **9**  | |
| 128 ~ 159 | 4   | ~22x    | **12** | |
| 160 ~ 191 | 5   | ~45x    | **16** | |
| 192 ~ 223 | 6   | ~63x    | **20** | ← 当前默认工作点 |
| 224 ~ 239 | 7   | ~126x   | **24** | 弱光，最强降噪 |

> **实现要点**：`dz_ag` 是**寄存输出**（不把 16bit 比较器 + 7 选 1 mux 串进 S6 关键路径），
> 且阈值全是 32 的倍数 ⇒ 直接用 `ag_s2[7:5]` 译码（等效 `ag/32`），
> `O_ag ≤ 239 < 256` 故位切片不越界。**已用脚本验证：位切片译码与阈值比较
> 在 `ag∈[16,239]` 全区间完全等价（0 处不一致）。**
>
> `I_ag` 来自 24MHz 域，模块内做 **3 级同步**（`ag_s0/s1/s2`）。AE 每 ~3 帧才动一次，够用。

> `MODE=0`/`EN=0` 时**输出中心行 RGB 原值（保留全部延时与几何）**，
> 所以切换 MODE 不会产生位移，两台效果可直接对比。

### 降噪强度直观对比（噪声尖峰幅度 `a` → 输出残余）

| `a` | 旧固定 `CORE_DZ=8` | 新 `dz=20`（63x 档） |
|---|---|---|
| 16 | 8 | **0** |
| 28 | 20 | **8** |
| 40 | 32 | **20** |
| 64 | 56 | **44** |

⇒ 在高增益工作点，**幅度 ≤20 的噪声被完全抹平**（旧版本只到 8），
这是本轮"上板噪点仍明显"的直接对策。

## 五、流水线与对齐（★ v2 重点改写）

> **v1 的教训（2026-10-07 时序违例）**：v1 把 blur→coring→unsharp→delta→限幅
> 全写成一条组合链，寄存器之间堆了 **约 18 级 LUT**，产生
> `u_image_enhance/u_line1_y/O_data_reg → u_chroma_denoise/...` 的 18 级路径
> （slack −0.036 ~ −0.057ns）。**v2 把每一级都寄存**，单级 ≤5 级 LUT，功能完全等价。

```
S1  RGB→Y=(77R+150G+29B+128)>>8；寄存 RGB / Y / col_cnt
S2  水平 [1 2 1]/4 得 hY；打包 {Yc,hY}=16bit；RGB 单独寄存（同写地址/使能）
S3  行延时 RAM ×3 → p1_y16(中心行) / p2_y16(上上行) / rgb_p1(中心行 RGB)
S4  blur = 垂直 [1 2 1]/4                        → 寄存
S5  diff_a = |Yc-blur|、符号                     → 寄存
S6  cored  = max(diff_a - CORE_DZ, 0)            → 寄存
S7  y_dn = blur ± cored；inc = cored >> SHARP_SH  → 寄存
S8  y_out = y_dn ± inc（限幅）；MODE 选择         → 寄存
S9  dmag = |y_out - Yc|、符号                    → 寄存
S10 RGB + delta → 限幅 → rgb_out
```

新增 7 级寄存（S4~S10），总延时 = **1 行 RAM + 约 10 拍**，
表现为画面**上移 1 行、右移约 10 像素**，与 `chroma_denoise` 同量级，肉眼不可察。

**★ 中心行 RGB 只需 1 级行延时的原因**：输出像素落在**中心行(row n-1)**，
而 RGB 与 Y 用的是**同一套写地址/写使能**，故 1 级行延时后 `rgb_p1` 与 `p1_y16`
天然严格同拍 —— 不需要额外的对齐逻辑，也不需要"当前行 RGB"的第三级 RAM。
（`cur_y16` 只用于垂直滤波取第 3 行，不参与 RGB。）

### ★v6.5 输出 `O_de`：**纯寄存器延时链**（v6.4 的"结构对齐"是错的，已废）

本模块输出比输入晚 **1 行 + 10 拍**。下游 `chroma_denoise` 用 `I_de` 驱动
**列计数器与行缓存地址**，而且它的计数器是"**de 为低就清零**"（这就是逐行对齐的机制）。

**v6.4 的错误做法**：把 `de` 与 RGB 打包进同一条行缓存（`u_line_rgb` 24→25bit），
用读出的位当 `O_de`。听起来"与流水线解耦"，实际**致命**：

> 行消隐期间列地址被钳在 **0**，行缓存读出的就是"**第 0 列那一位**" ——
> 而第 0 列是有效像素（写使能为 1 时写入）⇒ **`O_de` 在整个消隐期恒为 1**。
> 于是 `chroma_denoise` 的列计数器**永不复位**：地址以 1280 为模自由跑，
> 而行周期是 1650 拍 ⇒ **每行相位漂移 370 拍**。

由此推出的可量化后果（与上板实测完全一致）：

| 输出列 c | `p1` 抽头实际来自 | 画面表现 |
|---|---|---|
| c ≥ 1280−370 = **910** | 消隐期的**采样保持常数**（上一行最后一列） | **右侧 370/1280 = 28.9% 整片同一颜色**（实测为纯黑，黑区占屏 ≈27%） |
| c < 910 | 隔 370 / 740 列的像素 | 垂直滤波把远处像素混进来 ⇒ **横向色带** |

> 灰度/二值/Sobel 全部取自 `S_video_bright`（`gamma_lut` 输出），**绕过本模块与
> `chroma_denoise`** ⇒ 灰度画面完全正常，这个"彩色坏、灰度好"的迷惑现象正是由此而来。

**v6.5 修法**：`de` 只做**纯寄存器延时**，不经过任何行缓存 ——
`I_de → s1 → s2 → de_s3 → s4 → … → s9 → O_de` 共 **10 拍**，
与像素通路的 `1 行 + 10 拍` **相差恰好 1 个整行（1650 拍）**
⇒ 行内相位完全对齐，下游列计数器每次行消隐都能正确复位。
行缓存恢复 24bit。

> ★★ **通用教训（已写入模块头与 `line_delay_ram.v` 注释）**：
> **凡"靠 de/valid 复位计数器"的下游，de 必须在消隐期为低。
> 任何"从行缓存里取出的 de"都不满足此条件**（消隐期地址被钳位，读到的是有效像素那一位）。

**资源**：3 个行 RAM（16/16/**24**bit × 1280 深）+ 纯逻辑约 150 LUT / 约 470 FF，**无乘法器**。

### ★★ 行缓存必须强制块 RAM（这是本轮时序违例的根因）

本工程综合策略带 **`set area_option -packarea`（面积优先）**，
TD 会把 `line_delay_ram` 推断成**分布式 RAM（LUTRAM）**：
实测 `chroma_denoise` 的两个行缓存因此吃掉 **2816 个 LUT/slice**，
把全芯片 slice 占用推到 **88.03%**，直接引发布线拥塞型违例
（`place.qor` 布局后 WNS = **+11ps 通过**，`route.qor` 布线后 = **−70ps 失败**）。

已在 `line_delay_ram.v` 的 `mem` 声明上加
`/* synthesis syn_ramstyle="block_ram" */` 强制走 ERAM。

## 六、为什么不用有符号向量（★ 血的教训）

`chroma_denoise` 曾两次因 **Verilog「部分选择永远是 unsigned」** 而翻车
（彩色全黑 / 满屏蓝黄噪点）。本模块**刻意全程使用无符号运算**：

- 高通分量拆成 **幅度 `diff_a` + 符号 `sgn_neg`** 两条无符号线；
- 加法/减法分别走两条路径，各自显式限幅。

> 结论：**能不用 signed 就不用 signed**；一旦用了，绝不对它做部分选择。

- **只回退自适应**（保留 v6.5 的 `O_de` 寄存器链）：`ADAPT_EN = 1'b0`（回到常量 `CORE_DZ`）
- 快速回退（保留几何）：`EN = 1'b0`（等价 MODE=0，纯延时直通，`O_de` 仍正确输出）
- 彻底移除：删掉 `design_top_wrapper.v` 里的 `u_image_enhance` 实例，
  把 `chroma_denoise` 的 `.rgb_in(S_video_enh)` 改回 `.rgb_in(S_video_bright)`、
