## 〇、★ 最新根因（2026-10-07 下午）：tuser 领先量契约被破坏

### 症状

换上 `awb_frame` 后立刻出现（10-06 及之前没有）：

- 画面**持续抖动/横移**（板子平放桌面不动也在抖）
- 显示器**右侧一条长条区域显示不对**（错位/无画面）
- 颜色"一直在变"

### 机理（代码级证据）

`video_in.v`（DDR 写入器）拿帧起始信号做三件事：

```verilog
S_camera_frame_start_extend : I_camera_frame_start 被【拉宽成 8 个相机时钟】
S_fifo_rst = S_camera_frame_start_extend_3d          // ★复位窗口 = 8 拍的电平
S_frame_start = ~extend_3d & extend_2d               // 上升沿 → 切写指针 + 重载 DDR 基地址
```

⇒ **帧起始脉冲必须比本帧第一个数据字早 ≥ 8 个相机时钟**，否则 FIFO 的复位窗口会压在
帧首数据上，把它们当垃圾丢掉：

| 后果 | 现象 |
|------|------|
| 整帧在 DDR 里整体前移（丢 N 个字 = 5N 像素） | 右侧出现错位长条 |
| 每帧丢的字数不固定 | 画面横向抖动 |

**为什么丢的字数会不固定**：`S_csi_rx_clk`（MIPI 字节时钟）与 `S_ddr_clk`（DDR 用户时钟）
在 `camera_to_dsi_display.sdc` 里被 `set_clock_groups -asynchronous` 声明为**互异步**，
两者相位持续漂移 ⇒ 复位释放时刻相对数据流的相位每帧都在变。

**为什么 10-06 是好的**：旧实现（工程 `.al` 实际编译的**根目录 `awb.v`**）是

```verilog
assign O_tuser = I_tuser;                 // 0 拍，组合直通
数据经 signal_delay(DELAY_CYCLE=50)       // 约 53 拍
```

⇒ tuser **早约 53 拍**，复位窗口整个落在垂直消隐里，安全。
本模块初版只早 **1 拍** ⇒ 立刻踩坑。

### 修复：新增 `DATA_LEAD` 参数

只延迟【数据/valid/tlast】，**不延迟 tuser**（tuser 仍只走 2 拍寄存器）：

```
O_tuser = I_tuser + 2
O_tdata = I_tdata + 3 + DATA_LEAD
领先量  = 1 + DATA_LEAD = 33 拍（DATA_LEAD = 32，复位窗口的 4 倍）
```

- `DATA_LEAD` 必须 **≥ 12**（8 拍复位窗口 + 异步同步余量），必须 **远小于帧消隐宽度**
  （消隐上万拍）。
- **不要**把它改小到 0/1，否则立刻重现抖动。
- 资源代价：约 `DATA_LEAD × 97` 个 FF（默认约 3200 个）。

### 为什么单帧照片指标看不出来

同一场景连拍 3 张的量化结果（亮度/色比/削顶）**几乎完全一致**：

| 照片 | R/G | B/G | Y 均值 | Y 高频 | R 削顶 |
|------|-----|-----|--------|--------|--------|
| N1 | 0.9758 | 0.9770 | 157.0 | 5.90 | 0.13% |
| N2 | 0.9835 | 0.9908 | 157.8 | 5.11 | 0.04% |
| N3 | 0.9681 | 0.9764 | 156.9 | 5.52 | 0.08% |

⇒ **AE、AWB 都是稳的**（亮度波动仅 0.6%），问题纯粹是**逐帧的时序/几何不稳定** ——
静态统计指标天然看不出来，必须看"帧与帧之间"。

## 一、问题是怎么定位的（证据链）

用户上板照片的逐通道量化结果：

| 通道 | 均值 | ≥250 削顶占比 | 相邻像素差分 |
|------|------|---------------|--------------|
| **R** | **173.3** | **5.76 %** | 16.00 |
| G | 135.4 | 0.09 % | 16.65 |
| B | 144.2 | 0.43 % | 16.68 |

对照灰度模式照片，R 饱和占比仅 **0.05 %**。

### 链路

```
AWB 输出的通道比例没校准（偏红）
   → sat_enhance 把色度再放大 1.5 倍（SAT_GAIN=96）
      → 亮部 R 撞 255 被钳位（5.76 % 像素）
         → 钳位破坏 Y 守恒 → 亮度出现像素级抖动
            → 肉眼看到"粉红块 + 椒盐噪点"
```

### ★ 重要认知：灰度模式永远看不出这个问题

灰度画面只要亮度 Y，而灰度模式下 **R=G=B**，AWB 的"通道比例错误"对 Y 完全不可见。  
所以 **"灰度正常"既不能证明 AWB 正常，也不能证明 LSC 相位正确** —— 不要再用它当判据。

## 二、旧实现的结构性缺陷

文件：**根目录 `awb.v`** —— 工程 `.al` 清单里实际引用的就是这一份
（`isp/awb/awb.v` 是**未参与编译**的另一份副本，行为不同，查代码别查错文件）。

1. **帧内滚动统计**  
   `sum_r/g/b` 在 `I_tuser`（帧开始）复位为 **0**，之后沿帧内一直累加，而除法器
   `start = I_tvalid_r1` **每拍都发** ⇒ 增益是"从帧首累计到当前像素"的比值，随画面位置变化。  
   帧首 `ΣR` 极小甚至为 0 时，商 `ΣG·65536/ΣR` 会命中 `if(|in_r_x1[47:20]) → 20'hFFFFF`
   这条分支，**增益直接被置成 ≈16.0x，R 乘以 16 倍后削顶**。
2. **增益与像素错位**  
   数据经 `signal_delay` 延迟 53 拍，增益只延迟 (2 + 除法器 latency) 拍，
   二者相差约 (49 − latency) 拍。画面内容一变，白平衡就漂。
3. **无合理范围限制、无帧间平滑**  
   唯一的"限幅"是防溢出的 16x，物理上不可能需要这么大；帧间也没有平滑，增益会跳。

## 三、新模块 `awb_frame.v` 的做法

标准 ISP 流程：**统计整帧 → 帧末锁存 → 下一帧整帧统一应用**。

| 环节 | 做法 |
|------|------|
| 统计 | 累加整帧所有像素的 ΣR/ΣG/ΣB（32 bit，921600×255 ≈ 2.35e8 不溢出） |
| 跳过饱和 | `SKIP_SATURATED=1` 时跳过 r+g+b ≥ 750 的高光像素，避免白墙/高光绑架统计 |
| 锁存 | `I_tuser` 当拍锁存上一帧的 Σ（非阻塞赋值天然读到旧值），同时清零开新帧 |
| 计算 | `gR = ΣG/ΣR`、`gB = ΣG/ΣB`（G 为基准通道，增益恒 1.0x，不动整体亮度） |
| 应用 | 下一帧**整帧统一**用这组增益 ⇒ 不再需要 50 拍缓存，也没有错位问题 |
| 保护 | 增益钳位 [G_MIN, G_MAX]；Σ 异常(为 0)回退 1.0x；帧间 IIR 平滑 (3·旧+新)/4 |
| 资源 | 2 个 `divider` IP（旧版用了 8 个，省 6 个）；**无 BRAM**；`DATA_LEAD` 级 FF 延迟线（约 3200 FF） |

### 定点约定

- 增益 Q16：`20'h10000` = 1.0000x，`20'h08000` = 0.5x，`20'h20000` = 2.0x
- 像素乘法：`R_new = gR × R`（20×8=28 bit），取 `[23:16]` 为整数部分，
  `[27:24]` 非零则钳位 255（与旧实现一致，不会回绕）

### 延迟与相位（★ 与 `video_in` 的硬契约，见第〇节）

```
O_tuser = I_tuser + 2                       （只走 2 拍寄存器）
O_tdata = I_tdata + 3 + DATA_LEAD           （默认 DATA_LEAD = 32）
⇒ O_tuser 领先 O_tdata 33 拍（必须 ≥ 12 拍，否则帧首数据被 FIFO 复位吃掉）
```

下游 `data_96bit_to_128bit` 给 tuser 和数据**各 +1 拍**，相对领先量不变。

`O_tlast` 沿用旧实现的做法：**valid 的上升沿即"新的一行开始"**
（旧代码 `O_tlast = (valid_d1==0)&&(valid_d2==1)`），所以 `I_tlast` 输入未使用 —— 与旧模块
行为完全一致，下游不需要任何改动。

## 四、参数速查

| 参数 | 默认 | 含义 |
|------|------|------|
| `EN` | `1'b1` | 0 = 旁路（增益恒 1.0x），上板 A/B 对比用 |
| `G_MIN` | `20'h08000` | R/B 增益下限 0.50x |
| `G_MAX` | `20'h20000` | R/B 增益上限 2.00x |
| `G_DEADZONE` | `20'h00100` | 增益变化死区（1/256 ≈ 0.4%），抑制微抖 |
| `IIR_SHIFT` | `4'd3` | 帧间 IIR 时间常数 2^3 = 8 帧（越大越稳越慢） |
| `SKIP_SATURATED` | `1'b1` | 统计时跳过饱和像素 |
| **`DATA_LEAD`** | **`32`** | **★数据额外延迟拍数；O_tuser 领先 O_tdata (1+DATA_LEAD) 拍。必须 ≥ 12，勿改小** |

## 六、编译要点（★ 第一版编译报错的记录，已修复）

### 复用的 `divider` IP 端口定义（务必对照，写错位宽会直接报错）

模块定义在 `user_source/ip_source/divider/divider_gate.v`（`PH1P_LOGIC_SEQ_DIV` v1.1）：

```verilog
module divider(clk, denominator, numerator, rst, start, done, quotient, remainder);
  input  [31:0] denominator;      // 除数
  input  [47:0] numerator;        // 被除数
  input         start;            // 单拍脉冲启动一次
  output        done;             // 约 50 拍后单拍脉冲
  output [47:0] quotient;         // ★ 48 bit，不是 80 bit
  output [31:0] remainder;        // 未连接
  parameter PIPLE = 50;           // 流水线型，start 不需要保持
```

本模块用到的连接：

```verilog
denominator = sum_r_l   (32 bit)   ← ΣR
numerator   = {sum_g_l, 16'd0}  (48 bit)  ← ΣG 左移 16 位（Q16）
quotient    = q_r       (48 bit)   → clamp_gain() 取 [19:0]
```

### 第一版报的 5 条 Error 及原因

| 报错 | 原因 |
|------|------|
| `'O_data' is not declared in awb_frame.v(302/307)` | 输出寄存误写成 `O_data`，端口真名是 **`O_tdata`** |
| `'O_valid' is not declared in awb_frame.v(303/308)` | 同上，真名是 **`O_tvalid`** |
| `Ignore module module due to previous errors in awb_frame.v(57)` | 级联错误，修好上面两条即消失 |

另外自查中修掉一处隐患：`quotient` 原先声明成 `wire [79:0]`，与 IP 的 **48 bit** 不符，
一并改为 `[47:0]`，`clamp_gain()` 的溢出判据同步改为 `|q[47:20]`。

### 本地自检小工具 `tools/vlint.py`

写完新 `.v` 后，在工程根目录先跑一遍，能抓出上面这类笔误（只做文本级静态匹配，不替代综合）：
