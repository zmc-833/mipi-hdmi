# LSC 镜头色彩阴影校正（`lsc_shading.v`）

## 一、它解决什么

2026-10-07 白墙实测：**HDMI 画面中间偏绿、四周发紫**（肉眼确认，非手机拍摄伪影）。

这类色偏的根源是**镜头色彩阴影（Lens Color Shading）**——镜头边缘入射角大，
微透镜汇聚效率沿半径变化，且 R/G/B 三通道的变化斜率不同，于是"中心与边缘的
R:G:B 比例不一致"。

**为什么 AWB 和 CCM 都救不了：**

| 手段 | 作用范围 | 对本例 |
|:---|:---|:---|
| AWB（灰度世界） | 全局通道增益 | "中心绿+边缘紫"平均下来正好中性，AWB 认为没问题 → 无效 |
| CCM（3×3 矩阵） | 全局线性变换 | 全画面同一组系数，绿的还是绿、紫的还是紫 → 无效 |
| **LSC（本模块）** | 逐像素、随半径 | 对症 ✅ |

> 6504 定焦小镜头 + 1/2.7" 靶面是高发组合；SC520CS 三份资料（数据手册 V1.6、
> 应用指南 V1.4）均未暴露片内 LSC 寄存器，因此只能在 FPGA 侧校正。

## 二、插在哪里，为什么

```
raw10_unpacket_2lane（含 BLC，扣 64） → 【lsc_shading】 → uial2axis → demosaic → AWB → ...
```

- **必须在 BLC 之后**：sensor 模型 `raw = 信号·shading + pedestal`。
  先扣黑电平再乘增益，黑电平就不会被缩放，**角落依然是纯黑**；
  反过来（先增益后扣）会在角落残留灰雾。
- **必须在 demosaic 之前**：避免插值把增益不同的邻域像素混在一起。
- **必须在 AWB 之前**：让 AWB 统计到已校正的数据（否则白平衡仍被阴影污染）。
- 时钟域 `S_csi_rx_clk`（MIPI 字节时钟，720p60/2lane ≈ 34.5 MHz，周期约 29 ns），
  比 HDMI 像素时钟宽裕一倍以上，时序压力很小。

## 三、增益模型与参数

```
gain_ch(x,y) = 1 + (P_ch / 256) · ( r² / r²max )
   dx = 2x - (W-1),  dy = 2y - (H-1),  r² = dx² + dy²
```

- **中心增益恒为 1.0**，角落增益 = `(256 + P_ch) / 256`；
- `P_ch` 是带符号 Q8 参数（256 = +1.0）；
- 以 **G 为基准（P_G = 0）**，只调 `P_R` / `P_B`：
  - 边缘发紫（R、B 相对过量）→ **P_R、P_B 取负值**，衰减角落的 R/B；
  - 边缘发绿 → 把负值往 0 收，或给 P_G 正值。

### P 值 ↔ 角落增益对照

| P_ch | 角落增益 | 说明 |
|---:|---:|:---|
| 0 | 1.000 | 关闭该通道校正 |
| -25 | 0.902 | 轻微 |
| **-38** | **0.851** | **当前默认** |
| -50 | 0.805 | 较强 |
| -64 | 0.750 | 很强（一般到不了） |
| +38 | 1.148 | 反向（角落提亮该通道） |

换算：`P = (目标角落百分比 − 100) × 2.56`，例：想要 0.85 → (85−100)×2.56 = **−38**。

## 四、上板调参流程

1. **先拍一张白墙/白纸占满画面**的画面（正对屏幕肉眼看，别用手机斜拍）。
2. 观察四角：
   - 仍发紫 → `P_R`、`P_B` 一起更负（−38 → −50 → −64），每次改完重新编译；
   - 转绿/转青 → 往回收（−38 → −25 → −12）；
   - 中心与边缘一致 → 到位，记下这组值。
3. 一次只改一个变量，别同时动 AWB/CCM/sat_enhance。
4. 调好后**再做 CCM 的色卡标定**——色卡数据必须是 LSC 校正之后的，否则标定
   会把阴影一起"逆"进矩阵里。

> 典型轮次：2~3 次编译即可收敛。若怎么调都不干净，可能是镜头光轴偏心，
> 那时需要给模块加 `CX/CY` 中心偏移参数（当前默认取图像中心）。

## 六、注意事项 / 已知风险

1. **Bayer 相位**：已据 `mipi_to_raw_converter.v`（把 `[9:2]/[19:12]/[29:22]/[39:32]`
   打成 MSB=P0 的 32bit）与 `bayer_ypos = !v_cnt[0]` 核对为 BGGR。
   **若上板出现细密 2×2 彩色棋盘格**，说明相位反了 → 改 `BAYER_PHASE`（1/2/3 试一遍）。
2. **像素顺序**：`I_data[9:0]` 是每组最左像素（x 为偶数）。已核对，勿改。
3. **黑电平**：本模块在 BLC 之后，若后续调整 `.I_camera_black_level`，无需改本模块。
4. 本模块只校**颜色比例**，不校亮度渐晕（vignetting）。若四角明显偏暗，
   可另加一路亮度 LSC（三通道同增益），或先确认是不是镜头本来的渐晕。
5. 资源：约 10 个乘法器 + 少量逻辑，无 BRAM，无 DSP 硬核依赖。
