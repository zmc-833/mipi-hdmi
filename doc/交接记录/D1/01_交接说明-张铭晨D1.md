## 三、接口与参数（逐项给全）

### 4. YCbCr 转换系数

**我的代码里没有 YCbCr**。以下是方案 B 第 1.1 节指定"直接复用"的那份，出自**郭的** `user_source/hdl_source/chroma_denoise.v`（第 97~130 行），**Rec.601 定点化、分母 256**：

```
Y  =  0.299R + 0.587G + 0.114B   →  +77/256, +150/256,  +29/256
Cb = -0.169R - 0.331G + 0.500B   →  -43/256,  -85/256, +128/256, 再 +128 偏移
Cr =  0.500R - 0.419G - 0.081B   → +128/256, -107/256,  -21/256, 再 +128 偏移
```

原文写法（18 bit 有符号中间量，`>>>8` 前加 `+128` 做四舍五入，结果限幅 0~255）：

```verilog
wire signed [17:0] y_calc  =  18'sd77  * r_ext +  18'sd150 * g_ext +  18'sd29  * b_ext;
wire signed [17:0] cb_calc = -18'sd43  * r_ext + -18'sd85  * g_ext +  18'sd128 * b_ext;
wire signed [17:0] cr_calc =  18'sd128 * r_ext + -18'sd107 * g_ext + -18'sd21  * b_ext;
wire signed [9:0]  y_pre   =        (y_calc  + 18'sd128) >>> 8;
wire signed [9:0]  cb_pre  = ((cb_calc + 18'sd128) >>> 8) + 10'sd128;
wire signed [9:0]  cr_pre  = ((cr_calc + 18'sd128) >>> 8) + 10'sd128;
```

⇒ **要卡色度阈值，直接抄这 9 个数字，别自己重算**；注意 `+128` 是偏移量不是系数，别漏。

### 5. 像素坐标计数器（`pix_coord_gen.v`）

**位宽**：`O_pix_x[10:0]`（0..1279）、`O_pix_y[9:0]`（0..719）

**生成规则**

```
vsync 上升沿（场消隐期，de 恒 0）：x ← 0, y ← 0        ← 唯一归零点
de 有效 & last=1（行末像素）：     x ← 0, y ← y+1      （y=719 时回绕 0，兜底）
de 有效 & last=0：                 x ← x+1            （x=1279 时回绕 0，兜底）
```

**与 de / last 的对齐关系**

- `I_last` **必须与 `I_de` 严格同拍**（位级验证：3 帧共 **2160** 拍 `last=1 且 de=1`，`last=1 但 de=0` **0 拍**）。
- `I_vsync` **高有效**，其高脉冲落在场消隐期（行计数 726~730，此时 de 恒 0），所以"消隐期归零"与"de 分支"永不冲突。

**滞后拍数**

| 信号 | 相对 `I_de` 的滞后 |
|:---|:---|
| `O_pix_x` / `O_pix_y` | **0 拍**（与当前像素同拍） |
| `O_pix_x_1d` / `O_pix_y_1d` | 1 拍 |
| `O_pix_x_2d` / `O_pix_y_2d` | **2 拍**（消费模块用这个，与 `hdmi_mixer` 的 `S_video_data_2d` 同舞台） |
| `O_frame_done` | 在 vsync 上升沿起、脉宽 1 拍 |

**⚠️ 与 `hdmi_mixer` 内建计数器的差异（重要）**

`hdmi_mixer` 第 327~345 行那份计数器用"`user` 优先清零"写法，位级审计证明有两个副作用：
① **首行（r=0）整行 `S_x` 比真实列号小 1**；② 帧首像素采到上一帧残留 `S_y=720`。
两者只影响 `y=0` 一行（被 160×160 Logo 覆盖，上板看不见），但**画框一旦覆盖 y=0 就会错位**。
我的 `pix_coord_gen` 改用**场消隐期归零**，**无这两个偏移**。全队请统一用我这一份。

### 9. 公共总线位域划分（我的想法）

**已落地部分**（`box_draw` 现在实际吃的，只够画框用）

| 字段 | 位宽 | 说明 |
|:---|:---|:---|
| `valid` | 4 bit（每框 1 bit） | 0 = 该框无效，直接不画 |
| `xmin` / `xmax` | 4×11 = **44 bit** | 第 k 框 = `[k*11 +: 11]` |
| `ymin` / `ymax` | 4×10 = **40 bit** | 第 k 框 = `[k*10 +: 10]` |

⇒ 目标**无效时 `valid=0` 即可**，bbox 填 0 即可（退化框判断会兜住）。

**提议的完整目标列表总线**（方案 B 第 4 节 `{valid, cls, cx, cy, xmin, xmax, ymin, ymax, area}` 深度 4）

建议**每个目标打包成 96 bit**（对齐 12 字节，方便打拍 / 拼接），4 目标共 **384 bit**，另加 1 个帧头字：

| 位域 | 字段 | 位宽 | 说明 |
|:---|:---|:---|:---|
| `[0]` | `valid` | 1 | 1 = 本帧有效 |
| `[2:1]` | `cls` | 2 | 0=未分类 1=红球 2=蓝方块 3=绿三角 |
| `[13:3]` | `cx` | 11 | 质心 x，0..1279 |
| `[23:14]` | `cy` | 10 | 质心 y，0..719 |
| `[34:24]` | `xmin` | 11 | 外接框左 |
| `[45:35]` | `xmax` | 11 | 外接框右 |
| `[55:46]` | `ymin` | 10 | 上 |
| `[65:56]` | `ymax` | 10 | 下 |
| `[85:66]` | `area` | 20 | 面积 Σ1，全帧上限 921600 < 2²⁰ |
| `[95:86]` | 预留 | 10 | 后续（置信度 / 目标编号 / 帧龄） |

**帧头字建议**（1×32 bit）：`[7:0] tgt_num`（本帧有效目标数）、`[23:8] frame_id`、`[31:24] 预留`

**三条约定**：

1. **帧末有效**：整帧统计完在 vsync 上升沿一起锁存，总线在整帧内保持不变（消费方随便采，不会中途变）。
2. **深度固定 4**：不足 4 个时剩余槽位 `valid=0`，**不压缩、不留空位**，这样我的关联逻辑索引稳定。
3. **坐标域统一**：`x: 0~1279`、`y: 0~719`，与公共 `S_pix_x`/`S_pix_y` 完全同域，避免换算。
