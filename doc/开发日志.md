### 关键结论

- **雾感的真根因是黑电平一次都没扣**，不是 Gamma 参数问题。同类的高速逻辑陷阱：
  本工程同名 `.v` 文件散落多处，**只有 `.al` 清单里引用的那份才参与编译**
  （本例是 `isp/raw10_unpacket_2lane.v`，`uiisp_beta/` 下那份是闲置副本）。
  改代码前先 `grep *.al` 确认。
- **AE 看起来"不起作用"不等于 AE 失灵**：逆光下全帧平均被亮区绑架，AE 判定达标而停止加曝光。
  判断余量的土办法——按键能让画面变亮，就说明增益/曝光远没到顶，问题在测光或控制律。
- **A1 的一个重要性质**：权重做了归一化，**均匀照明场景（室外/室内均匀光）画面完全不变**，
  只在明暗分布不均时才见效。不用担心改了把好场景搞坏。

### 关键技术结论

- **插入位置**：RAW10 **BLC 之后**、demosaic 之前。sensor 模型 `raw = 信号·shading + pedestal`，
  先扣黑电平再乘增益 ⇒ 黑电平不被缩放，角落保持纯黑（反过来会在角落留灰雾）。
- **像素序与 Bayer 相位**（已逐级核对，避免棋盘伪影）：
  `O_raw10_data[9:0]` = 组内最左像素（x 为偶数）→ `mipi_to_raw_converter.v` 按
  `[9:2]/[19:12]/[29:22]/[39:32]` 打成 MSB=P0 的 32bit → `bayer_ypos = !v_cnt[0]`（偶数行=1）
  → 与 **BGGR** 一致（偶数行偶数列 = B）。
- **增益模型**：`gain = 1 + (P/256)·(r²/r²max)`，中心恒 1.0；以 G 为基准（P_G=0），
  边缘发紫 ⇒ `P_R/P_B` 取负（默认 −38 ≈ 角落 ×0.85）。换算 `P = (目标% − 100) × 2.56`。
- **单乘法实现**：把「r² 归一化」折进常数 `M = P·65536 / (r²max>>8)`，
  每像素只 1 次乘法得增益；`r²` 用平方展开 `dx_k² = dx0² + 4k·dx0 + 4k²` 免 4 个乘法器。
- **坑（已规避）**：`>>>` 只有两侧**都 signed** 才是算术右移 —— 本模块 r2s_*/M_*/dlt_* 全部
  显式 `signed` 声明并已静态检查。
- **疗效仿真**：合成 18% 径向色阴影，LSC 后残余色偏 **9.2% → 0.3%**（P=−38，与理论 0.852 自洽）。

## 2026-10-07 下午（周三）—— 抖动 / 右侧长条的根因定位与修复

### 现象（用户上板反馈）

换上 `awb_frame`（v6.2 / v6.2.1）后：**画面持续抖动**（板子平放桌面不动也抖）、
**显示器右侧一条长条区域显示不对**、颜色"一直在变"、画面偏糊。
对照：**10-06 及之前没有这些现象**。

### 定量分析（先排除"感觉问题"）

同一场景连拍 3 张，区域统计：

| 照片 | R/G | B/G | Y 均值 | Y 高频 | R 削顶 |
|:---|:---|:---|:---|:---|:---|
| N1 | 0.9758 | 0.9770 | 157.0 | 5.90 | 0.13% |
| N2 | 0.9835 | 0.9908 | 157.8 | 5.11 | 0.04% |
| N3 | 0.9681 | 0.9764 | 156.9 | 5.52 | 0.08% |

**结论**：亮度波动仅 0.6%、色比波动 <2%、R 削顶 ≤0.13%
⇒ **AE 与 AWB 都是稳的，不是它们在振荡**。
⇒ 问题必然是**逐帧的时序/几何不稳定**，单帧静态指标天然看不出来。

### 根因（代码级证据链）

1. `video_in.v` 用 `I_camera_frame_start` 做三件事：复位写侧 FIFO、推进 4 缓冲区写指针、
   重载 DDR 写基地址；关键是

   ```verilog
   S_fifo_rst = S_camera_frame_start_extend_3d;   // 该脉冲被【拉宽成 8 个相机时钟】的电平
   ```

   ⇒ **帧起始必须比本帧第一个数据字早 ≥ 8 个相机时钟**，否则复位窗口压在帧首数据上，被当垃圾丢掉。

2. `camera_to_dsi_display.sdc` 里 `set_clock_groups -asynchronous` 把
   **MIPI 字节时钟**（= `S_csi_rx_clk`）与 **DDR 用户时钟**（= `S_ddr_clk`）分成两个异步组
   ⇒ 两者**相位持续漂移** ⇒ 每帧被丢掉的帧首字数**不固定**。

3. 症状对应：整帧在 DDR 里整体前移（丢 N 字 ≈ 5N 像素）⇒ 右侧错位长条；
   前移量逐帧变化 ⇒ 画面横向抖动 ⇒ 观感"糊"。

4. **为什么 10-06 是好的**：工程 `.al` 实际编译的是**根目录 `awb.v`**：

   ```verilog
   assign O_tuser = I_tuser;              // 0 拍，组合直通
   数据经 signal_delay(DELAY_CYCLE=50)    // 约 53 拍
   ```

   ⇒ tuser 早约 **53 拍**，复位窗口整个落在垂直消隐里 —— 一直没暴露。
   而 `awb_frame` 初版只早 **1 拍** ⇒ 换上去立刻踩坑。

### 修复

`awb_fix/awb_frame.v` 新增参数 **`DATA_LEAD`（默认 32）**：只延迟【数据/valid/tlast】，
**不延迟 tuser**，恢复"帧起始领先数据"的硬契约。

```
O_tuser = I_tuser + 2
O_tdata = I_tdata + 3 + DATA_LEAD
领先量  = 1 + DATA_LEAD = 33 拍（复位窗口的 4 倍）
```

资源代价 ≈ `DATA_LEAD × 97` ≈ 3200 FF（当前 DFF 17091 / 35K，余量充足）。

### 经验总结（写进 README「已知问题」与 `awb_fix/说明.md`）

- **换掉任何"帧起始与数据之间有时序关系"的模块时，必须回头核对下游对相位的要求。**
  本项目里 `video_in.v` 要求 `tuser` 比数据早 **≥8 个相机时钟**（因 FIFO 复位窗口宽 8 拍）。
- **异步时钟组会放大"时序契约被破坏"的后果**：相位固定时只是整体偏移（不易察觉），
  相位漂移时就变成逐帧抖动。
